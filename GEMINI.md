# Описание Проекта
Проект: PushOccurrence
Язык: Go (Golang) 1.25+
Архитектура: Микросервис, реализующий паттерн Transactional Outbox.

# Стек технологий
- БД: PostgreSQL (драйвер pgx/v5).
- Брокер: RabbitMQ (amqp091-go).
- Доп. БД: MongoDB (mongo-driver).
- Конфигурация: JSON.

# Основные правила разработки
1. **Язык общения**: Русский.
2. **Безопасность**: Никогда не хардкодь пароли. Используй конфиги или переменные окружения.
3. **Обработка ошибок**:
   - Никогда не игнорируй ошибки (никаких `_ = err` без явной причины).
   - Используй `fmt.Errorf("...: %w", err)` для оборачивания ошибок.
   - Не используй `panic` в основном коде (только при старте `main`).
4. **Контекст**: Все функции, работающие с I/O (БД, сеть), должны принимать `context.Context` первым аргументом.

# Тестирование
1. **Тип тестов**: Предпочитаем интеграционные тесты с реальными контейнерами (Docker), а не моки.
2. **Структура**: Тесты должны следовать паттерну AAA (Arrange, Act, Assert).
3. **БД в тестах**: В тестах мы подключаемся к локальным портам (из docker-compose), создаем реальные данные и проверяем результат.

# Архитектурные правила (Outbox)
1. **Надежность**: Критически важно соблюдать порядок: Сначала подтверждение от RabbitMQ (ACK), потом коммит в БД (transferred = true).
2. **Сценарии**: Реализован гибридный подход (LISTEN/NOTIFY + Recovery Loop при старте).
3. **Транзакции**: Обработка сообщения должна быть обернута в транзакцию (`pgx.Begin`), удерживающую блокировку (`FOR UPDATE SKIP LOCKED`) до успешной отправки в MQ.
